Install opens a Terminal window and runs the install there, so you can watch every command

transparent proxy — recommended. Redirects at the DNS layer, so Claude Code still believes it reached Anthropic and Remote Control keeps working. It changes /etc/hosts, loads a pf rule and trusts the local CA system-wide, so it asks for your password and affects every process on this Mac — which is why it comes with the two guards below.
base-url — fallback. Writes ANTHROPIC_BASE_URL into ~/.claude/settings.json. No password and nothing machine-wide, so it is the right choice when you cannot or would rather not touch system files — but Claude Code turns Remote Control off while that variable names a non-Anthropic host.
Either way the script backs up your settings first, waits for the gateway to be healthy before repointing Claude Code, and prints what it is doing. Restart Claude Code when it finishes.

Guards the two things that keep this working while nobody is watching

Gateway watchdog restarts the gateway if its process dies — no password needed

pf redirect guard root daemon; keeps traffic actually reaching the gateway

Both run every 2 minutes and write nothing while things are fine. The watchdog checks the gateway is actually running — having a pid, not merely being registered with launchd, which keeps answering for a job whose process has died. The pf guard checks the real path end to end: that api.anthropic.com answers, and answers from this gateway. Neither touches anything while no /etc/hosts redirect is installed, so a rollback stays rolled back. If the guard cannot repair the path after four tries it removes the redirect entirely, because a Mac that reaches Anthropic directly beats one that cannot reach it at all.

Secondary provider where inference goes when the primary is out — endpoint, model and API key

The test sends one real, capped request through the secondary exactly as a failover would — same auth, same model translation — asking the model which version it is. It costs a fraction of a cent on a metered provider.
The key is written to the macOS Keychain, never to config.json — which only stores the service name. It is never sent back to this page, so the box above stays blank even when a key is stored; the green line at the top of this panel is how you check one is there.
