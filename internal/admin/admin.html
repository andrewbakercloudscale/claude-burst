Context

⚡ PAUSELESS COMPACTION Compact Sessions without the Pause: the summary is written in the background, and you never wait

Savings per day are charted under Compaction savings.
When the summary is ready, Burst normally waits for your next prompt before swapping it in. During a long run of tool calls that can take a while, and the session keeps growing well past Compact at. Tick this to swap the summary in straight away instead, in the middle of the turn. The turn that is running is sent unchanged; everything before it is replaced by the summary. Compaction then happens within about a minute of the session reaching the threshold.

The risk: it is not documented whether Anthropic accepts this. If it refuses, Burst quietly undoes the swap and resends the request as it was, so Claude Code never sees an error; the summary then waits for your next prompt as usual, and this setting stays off until you press Save again. The gateway log records mid-turn accepted or mid-turn REJECTED with Anthropic's reason.
A line such as ⚡ Claude Burst, pauseless compaction: done. Context down 88%, 666k → 78k: 1074 earlier messages now go as a summary appears under the prompt you send, in Claude Code's own window: when a summary starts, when it is ready and swaps in with that prompt, when the swap has cut the context, and if it fails or no longer fits. It comes from a UserPromptSubmit hook Burst adds to ~/.claude/settings.json and removes when this is off. Claude does not see these lines, so they cost no context. News that happens mid-turn shows on your next prompt.

Your session never stops to compact. Claude Code's own /compact makes you wait while it summarises. Burst writes the summary in the background while you keep working, and swaps it in on your next prompt. No pause, no lost place, nothing to type.

Why it matters: on the subscription every turn re-reads the whole conversation, so a turn at 400k tokens costs about four times one at 100k and uses up your limits four times as fast. Claude Code only compacts near the end of its 1M window.

How: when a session's context passes Compact at, Burst asks the same model, on your subscription and your session's own login, to summarise everything before your latest prompt (about 40 seconds, in the background). From your next prompt it sends that summary in place of those messages. Claude Code keeps its full history and sees no difference. Your CLAUDE.md and other session context are carried over word for word. Thinking from before the summary is dropped, as Anthropic requires when history changes.

If you run /clear or /compact, or rewind, the summary no longer fits and requests go through untouched. Each compaction costs one summary call, which reads the session from cache, and one cache rewrite, and pays for itself within a few turns. The usage panel marks each one with Started and Finished rows and a green drop in context.

Compact at: the context that triggers a summary (default 300k). Warn when at: a line in the gateway log and a flag in the table below once a session reaches this share of Compact at (default 80%, so 240k at the default threshold). Delay between compactions: the least time between two compactions of the same session (default 30 minutes), so a session that grows fast is not summarised over and over.

Repository overrides

Sessions in these repositories compact at their own size instead of Compact at above, or never on their own (/compact-async still works). Warn when at and the delay apply to each repository's own size. A repository is the folder holding .git above where Claude Code was started; every other repository uses Compact at.
Before: the context the session would have had at its latest summary without Burst. After: what it actually sent. Saved per turn: the difference. Net saved: what Burst saved on the session after paying for its summaries and cache rewrites (hover for the parts). How these are worked out, including what happens when a session would have outgrown the 1M window: see How the savings are calculated below.
How the savings are calculated

Burst replays each compacted session from metrics.jsonl, request by request, beside a "without Burst" twin: a context that grows by exactly what the real session grows by, but never takes Burst's drops.

Claude Code compacts the twin too. Without Burst the session would not grow forever: when the twin reaches about 950k tokens (95% of the 1M window, Claude Code's own auto-compact point, which it does not publish exactly), it is compacted back down to the size of one of Burst's summaries. So fifteen compactions can never claim more than one window's worth of saving at a time, and right after the twin is compacted it can be smaller than the real session. Those requests count against Burst.

Per request: twin context minus real context, priced at the model's cache-read rate (in a long session every resent token is a cache read). Net: the sum of those, less every summary call, less the extra cost of writing each shortened history to cache on the request after a swap, where the twin would only have read. The twin's own compactions by Claude Code are not credited back, so the net figure errs low.

All figures are API-equivalent: on a subscription the real effect is slower use of your limits, not a smaller bill.

Context & cache what context costs on your subscription and on overflow, and keeping it small

Only requests sent to the paid secondary are pruned. Every overflow request resends the whole conversation and every token of it is billed, and most of that is old tool output: files read and commands run many turns ago. Your subscription (the primary) is never touched: Anthropic caches its context, so rewriting history there would break the cache and use up your limits faster. Changes apply to the next request; no restart.
The note says how much was removed and that the tool can be re-run, so the model knows the output existed and how to get it back. Results under 1 KB are left alone. The cut-off moves in steps, not one result per turn, so the start of the conversation stays byte-identical for several turns in a row. That is what lets a provider that caches prompts reuse it. This is where most of the saving is.
Applies to every tool result, recent ones included. A 200 KB test log or page snapshot is mostly middle; the head and tail are where the command, the error and the summary usually are. The cut is marked in the text so the model knows it happened.
Keep recent: how many of the latest tool results are always sent in full (default 10). Raise it if the verdict above says pruned requests fail more often. Step: how many results the cut-off advances at a time (default 10); bigger keeps the prefix stable for longer but prunes a little less. Cap: the largest single tool result sent in full (default 40 KB).
Figures cover the last 7 days of metrics.jsonl. "Removed" is the share of the secondary's input pruning took out, estimated at ~4 bytes per token and priced at the secondary model's input rate. A re-run is the model calling a tool again, with the same input, after its output was stubbed: pruning cost a round trip there instead of saving one. If more than a quarter of stubbed calls are re-run, the verdict turns red. Cache figures come from what each provider reports; a provider that caches but does not say so shows 0%.

Sessions

Session handover Claude reads HANDOFF.md when a session starts and updates it when you close the window

Two Claude Code hooks in ~/.claude/settings.json. They only act in a repo whose root has a HANDOFF.md: create that file (even empty) to opt a repo in, delete it to opt out. Nothing here is related to routing; it lives on this page so you can see and adapt it.

When a session starts

On a new session or /clear (not on resume or compaction, which already carry the conversation), Claude gets the text below, then the newest handover section, the commits since HANDOFF.md last changed, git status and the repo's layout. {{file}} becomes the HANDOFF.md path.

When a session ends

Ending means /exit, Ctrl-D, /clear or closing the Ghostty window or tab. A background job then reopens a copy of the finished session with the writer model, so it has the whole conversation, and gives it the instructions below. It takes about a minute and a macOS notification says when it is done. Sessions with fewer typed prompts than the minimum are skipped. The writer can only read, edit HANDOFF.md and run read-only git commands. Cost: the writer re-reads the whole session, so a long session costs as much as one more turn of it; a cheaper model writes a thinner handover, and only costs less when the session ran on that model too, because the re-read comes from cache only on the same model. Opus, Fable and Sonnet read up to 1M tokens; Haiku stops at 200k, so it fails on longer sessions. Placeholders: {{file}}, {{now}} (local time), {{session}}.

Handover by repository

Every repository the handover hooks have acted in, most recent first, from . Last activity is what happened when a session last ended there; History lists the recent steps. View opens its HANDOFF.md here and Finder shows it in Finder. Delete all moves each file into a dated backup folder beside the log (with a MANIFEST.tsv of where each came from) and removes it from its repository, which also turns handover off there, since the hooks only act where HANDOFF.md exists. In a repository that tracks the file, the deletion then shows as a change to commit.

      

    

  


  

    
Session coordination  sessions share files without losing or sweeping up each other's work, and nobody waits

    

      
      
When several Claude Code sessions work in the same repository, the first one to edit a file becomes that file's master and is responsible for committing it. Other sessions can still edit the file: their changes go through, the master is asked to commit them at its next tool call, ahead of its own work, and the other session is told not to commit the file itself. Nobody waits on a master: a deploy held up by uncommitted work asks the masters to commit at once, and the deploying session carries on meanwhile. Files a background subagent is still working on never hold up its session. Three things are blocked while another session has uncommitted work in the repository: overwriting a whole file the master is still working on, sweeping commands (git add -A, git add ., git commit -a) that would commit someone else's work, and running a deploy or install script, which would ship that work although it is in no commit. A file is no longer shared once it is committed. A session also has to commit the files it is master of before it stops: if a turn would end with any of them uncommitted, the session is asked once to commit them (on this Mac only, never pushed, marked "WIP:" if unfinished), so a file passed to another session is always passed on committed. Every session is told these rules when it starts. It works through Claude Code hooks in ~/.claude/settings.json, added when you switch it on and removed when you switch it off; if a hook ever fails, the edit goes ahead as if coordination were off.

      

        

          
          
        

        

          
          
        

      

      
Once a file's master has done nothing for this long, the next session to edit the file becomes its master and commits it; the old master is told. Until another session needs the file, it stays with its master. If a master closes, the file goes to the session that asked for it, or else the one that most recently changed it too, or is released if there is none. The reminder tells a master that changes from other sessions have been waiting this long for it to commit them.

      

      

      
Is it working?
        
        

      
Counted from coordination's log. Coordinated is every time two sessions met over the same file or repository and coordination stepped in: a shared edit, a blocked action, a file taken over or handed on, or a session asking for a file. If it stays at 0, no two sessions have touched the same work yet, so there has been nothing to coordinate.

Stopped with uncommitted work: a session ended its turn with files it masters still uncommitted; it is resolved once each file is committed or handed to another session.

This Mac 
      

    

      
Keep working with the lid closed

      
Keeps Claude Code (and Remote Control) running with the lid shut, so you can carry on from your phone. macOS normally sleeps on lid close whatever else is running; this is the one switch that overrides it (pmset disablesleep, machine-wide, so it needs your password once per change). It also stops macOS napping Ghostty while its windows are hidden.

      

        
        
        
      

      
      
"Used" is a Claude Code turn, from this Mac or from your phone through Remote Control, or the lid being open. Once the time passes the Mac sleeps as usual; opening the lid wakes it and starts the time again, and if there is no network the hotspot is tried at once and then on the usual timing until the Mac is back online.

      

        
        
      

      

      


      
Join a hotspot when offline

      
With the lid shut, macOS will not join your phone's hotspot by itself (Instant Hotspot needs someone at the Mac), so a session left running loses the internet when you leave home Wi-Fi. This is the other half of keeping a session alive with the lid shut: Keep working with the lid closed above stops the Mac sleeping so Claude Code keeps working, and this keeps it online. Pick the hotspot here and Burst joins it for you when this Mac goes offline, so the session carries on in your bag and you can follow it from your phone through Remote Control. Opening the lid with no network also tries straight away and keeps trying, whatever When says.

      
Your phone must be visible to the Mac, or every join fails with "Could not find network". An iPhone only broadcasts its hotspot while something is connected to it or while Settings > Personal Hotspot is open on the screen. Before you close the lid and leave:
  • turn on Allow Others to Join and Maximise Compatibility in Personal Hotspot;
  • open the Personal Hotspot screen on the phone (or keep the Mac joined to it) until Burst has joined; once one device is connected, the phone keeps broadcasting.

      Permissions  what macOS lets Burst do, and how to fix what it does not
      
    
      
      
      Burst finds the repository each session runs in by looking for .git above it. Under Desktop, Documents and Downloads macOS asks first ("claude-burst would like to access files in your Desktop folder"). macOS remembers your answer per program, and an unsigned update counts as a new program, so the question came back after every update. Signing with a local certificate keeps one Allow for good. This page never looks inside the folders by itself, because looking is what asks.
      
      
      
      
      
      
      
        
        
        
        
      
      
      
      Check folder access looks inside Desktop, Documents and Downloads now, so macOS may ask for each one. Set up signing opens Terminal: macOS asks for your password or Touch ID, and the Keychain may ask for your login password.
      
      
      
    
      
  
      

  
      Health
      

  
  
  
      
    
      Guards the two things that keep this working while nobody is watching
      
      
      
    
      
    
      
      
      
      Gateway watchdog restarts the gateway if its process dies; no password needed
      
      
      
      
      
        
        
      
      

      
      
        
      pf redirect guard root daemon; keeps traffic actually reaching the gateway
      
        
      
        
      
          
          
        
      
      
      

      
      
        Both run every 2 minutes and write nothing while things are fine. The watchdog checks that the gateway program is really running (macOS can report a background job as loaded after its program has died) and restarts it if not. The pf guard looks after the redirect. pf is the packet filter, the firewall built into macOS; Burst adds one pf rule that sends Claude Code's traffic for api.anthropic.com to this gateway instead of straight to Anthropic, and other software (VPNs, security tools, a network change) can remove it. The guard checks that requests to api.anthropic.com really arrive at this gateway, and repairs the redirect if they do not. Neither does anything after you have reverted to normal Claude, so a revert stays reverted. If the guard cannot repair the redirect after four tries, it removes it, so Claude Code talks to Anthropic directly: working without Burst is better than not working at all.
